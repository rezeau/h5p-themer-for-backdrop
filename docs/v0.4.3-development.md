# v0.4.3 development — official MultiChoice Density

Unreleased implementation based on published v0.4.2 commit
`91415f7676b9091abd1bb2517fa28e5bd802d411`. The development build was deployed to
local backdrop2 under separate authorization. User-reported Firefox acceptance
is recorded separately from automated verification in the
[readiness review](v0.4.3-readiness.md). This review does not modify an installation.

## Scope and implementation

Exactly H5P.TrueFalse 1.8.24 and official H5P.MultiChoice 1.16.27 qualify on
Core API exactly 1.28, with development mode disabled. The backdrop2 mammals
activity uses content ID 9 and an internal iframe; its asset versions agree with
the installed MultiChoice manifest. This is source/HTTP evidence, not browser QA.

Server qualification re-reads the installed library and content through H5P's
integration API. Content major/minor must match that library's registry entry,
as must its library ID and resolved iframe embedding. The browser additionally
checks exact transport library/patch, integration identity, iframe realm and URL,
unique root/container, matching root instance and libraryInfo. Fixed container
adapters distinguish themed TrueFalse and MultiChoice questions. Transport never
supplies selectors. Patch identity remains server-authoritative because browser
libraryInfo does not expose it. This does not authenticate arbitrary modified
library files which retain official names and versions.

Version-3 transport, learner toolbar, sessionStorage key and failure behavior,
theme independence, initial original spacing and lifecycle remain unchanged.
Distinct qualified players share the tab's preference; duplicate embeddings of
one content ID remain rejected. DIV, external, nested, ambiguous and unsupported
players remain excluded. A qualified nested dependency does not qualify a container.

The existing controller changes only native Density classes on its proven root
and coalesces native resize notification to that instance. It calls no answer,
score, reset or solution APIs. No Density CSS, schema migration, new setting or
library modification is introduced. Saved and unsaved color previews are unchanged.

MultiChoice uses themed H5P.Question and native spacing/font variables. The shared
Question resize handler updates buttons and feedback layout. Its answer options,
tooltips and feedback may wrap differently after Density changes. The user reports
Firefox passes for Density, scoring/feedback/Retry, theme/session behavior,
keyboard/focus, zoom/responsiveness and console errors. Specific untested scenarios
and assistive-technology limits remain in the readiness review.
Small and Medium do not necessarily have distinct font sizes in native Core CSS.

## Automated regression scope

The existing complete PHP suite includes saved/live color previews, configuration,
imports, visibility, learner behavior and preserved historical readiness checks.
`tests/density-v043.php` adds exact MultiChoice version/content identity, unsupported
library, iframe, development mode, Core API, cache and mixed-library delivery checks.

The JavaScript integration suite consumes production PHP metadata for both
libraries. Tests cover matching and spoofed library identities, wrong patches and
versions, fixed container matching, duplicate/nested/external rejection, mixed
supported/unsupported players, state preservation, theme switching, session handoff,
storage failures, replacement/detachment, resize failure isolation, coalescing and
equal-height resize. DOM doubles do not establish computed browser layout or scoring.

Run existing suites with backdrop2 source definitions only, without bootstrapping
a site or loading settings.php:

```powershell
php -n tests/run.php --backdrop-root=C:/wamp64/www/backdrop2
$env:BACKDROP_SOURCE_ROOT = 'C:\wamp64\www\backdrop2'
$env:PHP_EXECUTABLE = 'C:\wamp64\bin\php\php8.3.18\php.exe'
node --test --test-reporter=spec (Get-ChildItem tests/js/*.test.cjs).FullName
```

## Manual Firefox test plan and remaining extensions

This is the detailed plan, not a claim that every subcase below was executed.
The six accepted tests and mixed-player report are enumerated in the readiness
review; cases not explicitly reported remain unverified in a real browser.

1. On the mammals and TrueFalse pages, start without a Density preference and
   verify original spacing and no pressed Density button. Choose Small, Medium
   and Large; confirm exactly one native class, usable controls and no clipping.
2. In MultiChoice, select an answer, cycle Density before Check, then Check and
   cycle again. Verify selected answers, score and feedback remain unchanged.
   Test incorrect and correct answers, solutions and Retry where available.
   A separate multi-select fixture is needed if the mammals item is single-select.
3. Exercise long/wrapped options, tips, feedback, images and solution indicators.
   Check iframe fit after each profile and after feedback/Retry; no resize loop,
   jump, stale height or horizontal overflow should appear.
4. Change every visual theme while holding Density fixed. Verify color behavior
   and both administrator color previews. Reload and navigate between MultiChoice
   and TrueFalse in the same tab; the explicit Density preference must follow.
5. Test keyboard-only operation, visible focus, Enter/Space, reading order and
   announcements. Check 200% zoom and 375 px width, forced colors and a screen
   reader. These last two need explicit evidence, not inferred conformance.
6. In an authorized test fixture, combine distinct TrueFalse and MultiChoice
   players with an unsupported player; only qualified players should change.
   Test duplicate content IDs, late initialization, replacement and detach.
7. Verify storage-denied behavior, browser back/forward restoration, switch OFF
   and unsupported library versions. Record Firefox version and console errors.

## Deployment requirements and limits

The initial backdrop2 deployment was separately approved and completed. Future
deployment changes require separate approval. Replace only the module on backdrop2 with
the complete matching development files, refresh relevant Backdrop output and JS
aggregation caches, then load fresh pages. Existing open pages retain loaded code.
Use the existing Density checkbox/PHP override and learner-selection prerequisite.
Do not modify the retired site. No H5P content, library, database update or new
configuration key is required. Preserve a v0.4.2 code backup; this phase introduces
no additional configuration rollback step beyond the baseline's existing rules.

Other patches and libraries require separate qualification. No broader browser,
accessibility, DIV, container or nested-content support is claimed. No Live Density
Preview, release ZIP or publication is part of this phase.
