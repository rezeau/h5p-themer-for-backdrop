## Implementation review

Reviewed every tracked diff and both initially untracked implementation files,
then updated documentation and prepared draft v0.4.3 release notes. Production
logic changes are confined to server/browser Density qualification; module metadata
and administrator help describe the expanded exact scope.

- PHP registry accepts only H5P.TrueFalse 1.8.24 and H5P.MultiChoice 1.16.27.
  Qualification re-reads installed library identity/patch and main-content ID,
  library ID, major/minor and resolved iframe embedding. Unsupported main libraries
  cannot qualify through their dependencies or node claims. Development mode and
  APIs other than exactly 1.28 fail closed.
- Browser qualification checks the version-3 player record against a fixed
  library/patch allowlist, matching integration and instance library identity,
  unique internal iframe, same document/realm, root instance, initialized root
  and corresponding themed question container. Selectors are not supplied by
  content or transport. Existing optional machineName behavior is preserved;
  versioned name and major/minor remain mandatory. Patch verification is supplied
  by the server, since browser libraryInfo lacks a patch field.
- Mutable ownership records remain per actual frame/document/root/container/API/
  instance tuple. Distinct qualified players share one learner preference while
  retaining their own original spacing and resize lifecycle. Duplicate embeddings
  of one content ID remain rejected. Unsupported siblings, nested players,
  external frames and DIV rendering remain excluded.
- Changes still use only native root classes and targeted, coalesced resize.
  No new CSS or answer/score/reset/solution calls were introduced. Storage failure,
  readiness handoff, replacement/detach and resize-failure isolation are covered.
- v0.4.2 controls, session key/enum, theme independence, original spacing before
  a choice, strict activation/override policy and internal reset API are retained.
  Legacy Density fields and imports retain their existing compatibility contract.
  Configuration/schema, color runtime, saved/live previews, learner toolbar/picker
  and CSS files have no changes relative to the approved baseline.

The allowlist checks names and versions, not a cryptographic signature of installed
library files. It does not certify arbitrary forks retaining official identities.

## Deployment discrepancy resolution — prior investigation

The separately authorized deployment installed five matching runtime files on
backdrop2 and refreshed caches. Its initial final verification stopped because a
complete-row hash of `h5p_nodes` changed after HTTP checks.

A subsequent read-only transaction confirmed the current table matched the
recorded after-hash. Setting only `filtered` to an empty string for content IDs
8 and 9, entirely in memory, reproduced the exact pre-deployment table hash
`90f4dcd3b852e1976745286ecda2ba48fc250dc604693ce38f8a853d20ad497f`.
This hash-validated reconstruction establishes unchanged authored JSON and other
columns for all eight rows. Only the two cached `filtered` fields were populated:
1,099 bytes for TrueFalse and 1,822 bytes for MultiChoice. H5P's normal rendering
path filters missing cached parameters and persists those derived values.

This resolved discrepancy is not a remaining blocker. The original deployment
report is retained as historical evidence of the initial stop. Future deployment
verification should retain consistent row-level snapshots and per-content raw
and semantic authored-JSON hashes, with derived fields compared separately.

## Remaining untested or unreported cases

- Other browsers and exact Firefox-version coverage.
- Screen-reader announcements, Windows forced colors and accessibility conformance.
- Separate multi-select/partial-scoring variants, unusually long options, image
  options, tips/popups and solution-display edge cases beyond the reported content.
- Real-browser duplicate embeddings, AJAX insertion/removal, iframe/instance
  replacement, BFCache/back-forward restoration, late readiness and resize failures.
- Real-browser denied/corrupt session storage, installation base-path edge cases
  and explicit internal reset/original-class measurements.
- A full v0.4.2-to-v0.4.3 rollback rehearsal. No migration was introduced, but the
  restoration procedure itself has not been exercised.

Several of these have automated coverage, which is not substituted for real-browser
acceptance. Other library versions, DragQuestion, Blanks Density, Question Set,
Interactive Book, DIV/nested/external rendering and Live Density Preview remain
outside scope and are not release claims.
