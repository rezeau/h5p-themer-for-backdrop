## Behaviour and implementation

Only administrator-permitted colour themes are selectable. When the five built-ins
and both named custom themes are enabled, the rows are Daylight, Lavender, Mint,
Sunset, Dark, Colorblind Friendly and High Contrast Light. Other custom themes
continue to use their existing tokens/labels and visibility policy; the UI does
not hard-code seven names or bypass administrator visibility.

The full server catalog, metadata version 2, palette keys, icons and CSS bundle
remain unchanged. `site_default` and `core` remain internal states. The learner
controller derives a separate presentation list excluding those two entries and
passes it to the decorative picker. The native select uses that same colour list.
No saved values are remapped to Daylight or another palette.

When following site settings, the native select includes the disabled placeholder
**Using site settings**. When restoring explicit Core, it includes **Using original
H5P colours**. The enhanced closed control displays the same text, with no palette
swatch and no falsely selected colour row. Exploring the list uses an active
candidate separate from the committed selection. Escape cancels; a user commit
chooses and saves the exact colour token. A disabled placeholder is not a selectable
colour entry. Native fallback remains usable if icons/CSS/popover support fail.
Opening from a hidden state and pressing Tab/Shift+Tab without exploring closes
the enhanced list without selecting Daylight. Explicit Enter/Space or pointer
selection commits a colour; keyboard exploration followed by Tab retains the
existing candidate-commit behaviour.

The small Reset icon sits immediately beside the dropdown, before the existing
help button. Its native button name and title are both **Use site default theme**;
the glyph is decorative. Reset removes only the existing learner-theme session key
and restores effective administrator settings. It is disabled while already
following those settings. A focused button becoming disabled transfers focus to
the visible theme control, including browsers which immediately blur disabled
buttons. There is no new Core-selection button.

The Reset is theme-only. It does not reset Density, answers, scoring or solution
state. Density controls, native controller, transport version 3 and session key
are unchanged for qualified TrueFalse 1.8.24, MultiChoice 1.16.27 and Blanks 1.14.37
on Core API exactly 1.28. Iframe ownership/isolation and colour previews are unchanged.

## Defaults, preferences and failure handling

- Site settings may resolve to Core, a built-in or a custom theme, including a
  theme hidden as an explicit choice. The placeholder represents following those
  settings; it never pins the currently effective palette. A fresh administrator
  default is followed when matching updated page metadata/styles arrive.
- Saved `core` remains explicit through reload/restoration and administrator
  changes, until a colour choice or Reset. It is never treated as Daylight.
- Following Site default is represented by absence of the theme session key.
  A literal stored `site_default` already follows the existing invalid-token
  cleanup path, with the same resulting internal state.
- Stable custom IDs survive renames. Hidden/deleted/unavailable choices follow
  existing Site-default fallback and scoped preference cleanup. Unrelated session
  data and the Density preference are not cleared.
- BFCache restoration revalidates the existing preference against the attached
  metadata and updates placeholders/Reset without duplicate writes.
- Storage failures retain current-page operation. Failed removal cannot erase an
  inaccessible stored value; that older preference may return on a later page
  if storage becomes accessible. This is the existing storage-failure contract.
- A valid catalog always includes Daylight internally, so hiding all optional
  themes leaves one selectable colour. A genuinely empty or malformed catalog
  remains fail-closed, without clearing stored preferences or inventing choices.
  An empty presentation given to the decorative component restores native fallback;
  the controller also defensively disables a select without colour choices.

## Firefox acceptance evidence and reference checklist

The user reports that all six Firefox acceptance tests passed on the deployed
selector milestone, including the two approved UI corrections. This is user
evidence, separate from the automated results above. Individual test transcripts
and browser/assistive-technology versions were not supplied with that report;
no additional screen-reader, forced-colour or cross-browser qualification is inferred.
The following original checklist remains a reference for further regression work.
Seven colour choices apply only when all seven are permitted. The accepted test
configuration instead has six choices: Colorblind Friendly is the administrator
default and intentionally hidden; schema version 2 is preserved.

1. With the five built-ins and two named custom themes visible, verify exactly
   seven selectable rows in the correct order. Hide an optional theme through
   separately authorized administration and verify it disappears from both UIs.
2. With no preference and with defaults set to a colour or Core, verify **Using
   site settings**, no checked colour, disabled Reset and no unexpected palette
   change. Repeat with a hidden custom administrator default.
3. Restore a previously saved `core` preference. Verify original H5P colours,
   **Using original H5P colours**, no checked colour and enabled Reset. Open and
   cancel the list; no palette or storage change should occur.
4. Choose every permitted theme. Verify colours, persistence, Reset enabling,
   keyboard navigation, typeahead and readable labels. Reset using pointer and
   keyboard; verify the site settings return and focus lands on the theme control.
   Ensure Reset does not submit a form or activate repeatedly while disabled.
5. Exercise enhanced and native fallback controls, zoom at 200%, 375 px viewport,
   long labels, forced colours and a screen reader. Verify placeholder/value
   announcements, Reset name, disabled state, Escape/Tab and focus indicators.
   The theme/Reset/help tracks and separate Density track need computed-layout acceptance.
6. On qualified TrueFalse, MultiChoice and Blanks, set Density, answer/check an
   activity, switch themes and Reset. Verify Density, answers/score/feedback and
   native Retry/Solution behaviour remain independent. Include an unsupported
   fourth player and confirm Density isolation.
7. Test reload/navigation/back-forward restoration, rename/hide/delete, invalid
   preferences, denied storage and unavailable styles. Verify truthful placeholders,
   fallback announcements and no console errors or unexpected session writes.

Earlier user-reported Firefox passes remain separate evidence for the committed
Density milestones. The current six-pass selector report does not establish
coverage of every item in this longer checklist or exhaustive layout/state combinations.

## Follow-up: two Firefox-reported selector UI regressions

The initial selector build was subsequently deployed for user Firefox testing.
The user reported a toolbar collision and a repeated site-settings placeholder.
Both follow-up fixes were subsequently deployed and included in the user's
completed Firefox acceptance. Their source and deployment bytes match.

The collision is explained by the desktop media rule: help moved to column 3
when Reset was added, but Density still explicitly occupied column 3. Both
therefore shared row 2. The correction gives Density its own fourth track and
extends the theme label across the first three tracks. The dropdown retains
`minmax(0, 1fr)`/`min-width: 0`, the icons keep automatic tracks and the existing
gap separates help from Density. Below 48em, the three theme tracks remain on
row 2 and Density on row 3; Density actions retain flex wrapping. No positioning
offset or fixed toolbar width was introduced. This is a source-code diagnosis;
the automated suite does not measure computed geometry or Firefox zoom.

The duplicate site-settings text came from Reset passing the placeholder text
to the existing visible, polite status region. Reset now leaves that warning
region intact and sends the distinct **Theme reset.** event to a separate,
initially empty, mounted polite/atomic region. It uses the existing visually
clipped accessibility technique; it is not hidden from assistive technology.
It does not repeat either placeholder. Colour selection relies on native
select/combobox value semantics and clears the Reset message, avoiding an extra
live value echo. Invalid saved-preference fallback and partial-player warnings
still use the existing visible live region. Existing focus transfer, labels,
tooltip, disabled state, tokens and persistence are preserved. Actual spoken
output depends on the browser/screen-reader pair; no detailed AT transcript was supplied.
