## Implemented and accepted behavior

The existing strict boolean setting
`$settings['h5p_themer_native_density_enabled'] = TRUE;` is still required.
Learner theme selection must also be enabled for learner Density controls. Density
remains limited to qualified top-level internal-iframe H5P.TrueFalse 1.8.24 players
on Core API exactly 1.28. Library support has not expanded; unsupported players
retain original Density and existing color/picker compatibility behavior.

Small / Medium / Large T buttons sit beside the theme picker and wrap at narrow
widths. **Use theme Density** clears the explicit override. Precedence is learner
override > current theme's saved Density > each player's original native Density.
Theme/color switches, including Core and immutable built-ins, preserve an override.
All-null Core/built-in catalogs still deliver learner capability. No theme schema
or authored H5P content is modified.

The native controller alone owns Density classes, per-player originals, targeted
resize, state and persistence. One preference is shared per installation and browser
tab: `h5p_themer:learner-density:v1:<validated basePath>`. Standard sessionStorage
reload/navigation/opener-copy semantics apply. Invalid data falls back to theme
mode; reset removes only this key. Storage failures preserve current-page operation
but may leave older stored data. This does not save H5P answers or account preferences.

Native buttons retain accessible names, aria-pressed, visible focus, non-color
selection cues and keyboard operation. Mode/scope text and dedicated polite state
announcements are visually hidden per the accepted compact-layout refinement.
The decorative theme picker and native-select fallback are unchanged.

Previews remain representative color-only samples. **Live Density Preview remains
deferred** and is not part of learner Density controls.
