# v0.4.2 development — independent learner Density

Unreleased development based on published v0.4.1 commit
`02900d937e37319e4023f7016e0d03a1d2b8d5ca`. The controlled local backdrop2 code
upgrade and administrator checks passed. The user subsequently reported manual
Firefox acceptance; its scope and remaining limitations are recorded in the
[v0.4.2 release notes](release-notes-v0.4.2.md). No release has been published.
Historical release records remain unchanged.

## Administration and compatibility

Global settings provides **Enable native Density controls**, disabled by default.
It stores the optional strict boolean `native_density_enabled` in
`h5p_themer.settings`. Learner theme selection remains a prerequisite.

An explicitly present PHP `h5p_themer_native_density_enabled` overrides it:
TRUE enables, FALSE disables, and any other type (including NULL) disables with
an administrator diagnostic. The checkbox displays the effective forced state,
is disabled under the override, and never overwrites its saved preference.
Removing the override returns control to the checkbox. Environment values are
not migrated or exported into portable configuration. A changed override rejects
a stale settings form, including during locked submission.

Old settings may omit the new field and remain unchanged on an unchecked save.
No theme-schema migration, new visibility policy or activation replay is needed.
The independent installed schema remains 1003. Existing incomplete activation
must be resolved through its established reviewed workflow, not bypassed.

## Theme definitions and imports

Visual themes now affect colors only. No saved Density profile, including a
custom Global Default, is sent to the native controller. Density inputs and the
overview column are removed. Edit preserves the existing internal value;
duplicates preserve their source value; new themes keep the compatibility seed.
Forged submissions of the removed field are rejected.

Schema-1/2 theme definitions retain the required legacy enum and its validation.
Exports preserve it. The existing guarded schema-2 create-only single-theme
import remains supported; updates, bulk theme/policy synchronization and overwrite
remain rejected. Import never activates a saved Density value for playback.

## Learner behavior

The toolbar has exactly three native buttons: Small, Medium, Large. Native
activation, accessible names, aria-pressed, focus, equal targets, wrapping and
dedicated polite announcements are preserved. Mode/scope descriptions remain
visually hidden. The decorative theme picker and native-select fallback are unchanged.

Before an explicit choice, no size button is pressed and the original activity
spacing is untouched. H5P's unclassified Core 1.28 CSS uses Small variables and
scaling 0.6; Large is not a synonym for original spacing. Native profile changes
before the first override remain H5P-owned. Each player's original is retained
independently once Themer applies an override.

A choice applies to all qualified ready players on the page and survives visual
theme changes. Saved theme Density is never a fallback. The visible reset button
is removed: learners cannot return to original spacing through this toolbar
during the session. The internal validated `resetOverride()` removes only its
own session key and restores each player's original spacing.

The sessionStorage key remains `h5p_themer:learner-density:v1:<validated basePath>`.
Existing explicit v0.4.1 enum preferences retain their meaning. Missing/invalid
preferences mean original spacing. Standard tab cloning/restoration semantics
apply. Storage failures leave current-page controls usable; an older stored value
can reappear after a failed write. Preferences are not account settings or answers.

## Runtime and deployment

Density transport version 3 contains learner readiness and bundle identity, with
qualified player records delivered separately. Legacy global/profile mappings
are absent. Older/newer transports and legacy mapping fields fail closed.
The controller remains the only class/resize/state owner; public snapshot and
subscription APIs are unchanged. Qualification stays Core API exactly 1.28 and
top-level internal-iframe H5P.TrueFalse exactly 1.8.24. Unsupported content,
editors, nested/external/DIV players and ambiguous duplicate identities are excluded.

Deploy matching PHP, JS and CSS coherently. Refresh deployment caches only in a
separately authorized site context, then reload playback; old open pages keep
their loaded code. Disabling the feature does not erase stored preferences.

Back up code, configuration, settings and database before an upgrade. v0.4.1's
strict settings validator does not recognize the new optional key. Once it has
been saved, code-only rollback is insufficient: restore pre-upgrade settings
with the old code. Do not uninstall/reinstall, replay update hooks, delete a
visibility journal or rewrite saved theme definitions as an upgrade technique.

## Acceptance coverage and remaining checks

The numbered list below is the original acceptance plan, not a claim that every
item passed. Installed-site administrator checks used the real Backdrop Form API
and rendered HTML. Manual Firefox passes were reported by the user for all three
Density choices, theme independence, persistence across reloads/activities,
TrueFalse scoring/feedback/Retry, keyboard navigation and visible focus,
no console errors, 200% zoom and a 375 px viewport. Agent-driven Firefox learner
testing was blocked by Windows browser automation policy and supplies no passes.

1. Install only after approval into an explicitly authorized disposable site.
2. Verify fresh defaults, checkbox save, PHP TRUE/FALSE/invalid overrides and diagnostics.
3. Verify no Density input in Add/Edit/Duplicate/overview; colors and imports still work.
4. With cleared test-session preference, verify original spacing and all buttons unpressed.
5. Test Small/Medium/Large, all visual themes and hidden custom Global Default.
6. Verify two players with different originals, unsupported siblings and no duplicate effects.
7. Verify same-tab reload/navigation and existing v0.4.1 enum preference restoration.
8. Verify keyboard operation, focus retention, 200% zoom and narrow layout.
9. Verify answers, scoring, feedback, Check and Retry remain unchanged.
10. Verify no console errors and coherent version-3 delivery with aggregation enabled.
11. Check forced colors and a screen reader where available; do not infer acceptance.
12. Rehearse the settings-aware upgrade/rollback on a disposable copy before release.

Live Density Preview and broader library support remain deferred. A controlled
local v0.4.1-to-v0.4.2 deployment and checkbox conversion were exercised, but a
complete upgrade-and-restore rehearsal was not. Rollback, Windows forced colors,
screen-reader announcements, real-browser unsupported/multi-player scenarios,
internal reset/original-class inspection and BFCache/replacement acceptance remain
NOT TESTED. Automated fixtures cover the corresponding implemented safeguards;
they do not substitute for browser acceptance.
