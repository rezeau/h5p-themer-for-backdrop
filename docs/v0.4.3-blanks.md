## Compatibility assessment

Blanks calls `H5P.Question` with type `blanks` and `theme: true`, producing the
themed question container expected by the fixed adapter. Native CSS consumes
the existing spacing/font variables, so root Density classes supply the changes.
No controller, transport, persistence, control or resize architecture change is
needed; production logic changes are only exact registry/adapter additions.

On native `resize`, Blanks calls `resetGrowTextField()`, which invokes
`autoGrowTextField()` for each input. It measures the current input font, text and
available question width in a deferred callback and requests an inline width.
The method does not change answer values, mark answers, reset the task or focus
an element. Separate-lines mode leaves sizing to native CSS instead.

Native CSS also applies a `6em` minimum input width. Thus the JS inline width
request is not a guarantee of the final computed width. Input boxes are single
line with overflow handling; surrounding text and feedback must be checked for
wrapping in the actual browser. Very narrow containers, long/non-Latin answers,
tips and correctness decorations need manual measurements.

An input ResizeObserver debounces a native resize event by one second. This is
existing library behavior, not a new Themer timer. The shared Question handler
also updates button/feedback layout. Settling time, clipping and absence of a
resize loop remain browser acceptance checks.

Enter navigation, Tab/Shift-Tab behavior, labels, feedback/solution rendering and
Retry are owned by the native library. Retry clears answers and resizes by native
design; Density must not call it. When auto-check is enabled, moving focus away
from a filled input can natively check that answer, including when moving to a
toolbar button. The Density API itself does not synthesize blur or answer events;
manual testing must distinguish native auto-check from a Density side effect.

## Implementation and boundaries

Exactly TrueFalse 1.8.24, MultiChoice 1.16.27 and Blanks 1.14.37 qualify on Core
API exactly 1.28. Server checks retain installed library identity/patch, main
content ID/library ID/major/minor and resolved iframe requirements. Browser checks
retain matching transport/integration/instance identity, unique iframe/root and
realm, root-instance ownership and fixed themed container selectors.

Only `.h5p-question.h5p-theme.h5p-blanks` was added as the new container adapter.
DIV, external, nested, ambiguous and unsupported players remain excluded. Other
libraries such as Mark the Words remain suitable negative controls. Distinct
qualified players share a session preference; each retains independent original
spacing and targeted resize ownership. Duplicate content embeddings remain rejected.

The existing three controls, version-3 transport, session key, storage failure
handling and theme independence are unchanged. No new Density CSS, configuration
key, schema, H5P content/library update, answer/scoring API call or Live Density
Preview is introduced. Existing color preview/runtime code is unchanged.

## Extended manual test plan

The detailed plan below is retained for future qualification. The six reported
passes do not establish that every optional subcase in this plan was exercised.

1. Start with no Density preference. Verify original spacing and no pressed
   Density button. Select Small/Medium/Large; inspect exactly one native class,
   input/button sizes, paragraph wrapping and iframe fit after settling.
2. Enter short, long and non-Latin answers. Cycle Density before Check, after
   incorrect/correct feedback, after Show solution and after Retry. Verify text,
   scores and state persist through styling changes; only native Retry resets
   answers. Check tips, solution text, correctness markers and disabled inputs.
3. At 200% zoom and a 375 px viewport, verify computed input minimum widths,
   no clipping/overflow and readable feedback. Exercise separate-lines on/off
   and auto-check on/off using separately authorized additional fixtures if
   the supplied activity does not expose those variants.
4. Test Tab/Shift-Tab, Enter between inputs and native buttons, focus indicators,
   selection/caret usability and labels. In auto-check mode, verify native blur
   evaluation behaves consistently when moving to Density controls. Test forced
   colors and a screen reader; do not infer those results from keyboard checks.
5. Hold Density fixed while switching themes, reloading and navigating between
   all three qualified types. Verify independent tab-session persistence and
   colors, including saved and unsaved administrator color previews.
6. Use a mixed page with distinct TrueFalse, MultiChoice, Blanks and an unsupported
   Mark the Words player. All three qualified players should respond to Density;
   the unsupported player should retain spacing. Theme selection should still
   operate under its separate compatibility rules. The earlier three-player
   acceptance page no longer provides an unsupported Density control by itself.
7. Test duplicate embeddings, replacement/detach, late initialization, storage
   denial and back/forward restoration. Wait beyond the native one-second input
   observer delay after layout changes; verify settling without a resize loop,
   stale iframe height or console error. Record Firefox version and results.
